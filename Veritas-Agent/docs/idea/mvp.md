# Veritas MVP Build and Submission Plan

AWS First Commit Hackathon (September 2026)

## 1. The Winning MVP Slice (P0)

Judges evaluate working usability and tangible verification depth, not superficial features across dozens of screens. The Veritas MVP focuses on a single, airtight vertical slice:

- **Domain:** Section 7 Insolvency and Bankruptcy Code (IBC) application.
- **Client Records:** Two uploaded documents with a deliberate factual conflict (a Loan Sanction Letter stating Rs. 4.85 Crore and a Bank Default Certificate stating Rs. 5.20 Crore).
- **Draft Brief:** An editable working brief generated by the Writer Agent with linked citations.
- **Verification Scenarios:**
  1. *Genuine Citation:* Correctly identified and matched against the authentic judgment text.
  2. *Invented Citation:* Cleanly identified as Unresolved, highlighted in the evidence drawer, and blocked from reviewed export.
  3. *Quote Mismatch:* Case identity confirmed, but quoted language flagged for discrepancies against the primary text.
  4. *Factual Conflict:* Discrepancy between the two client records displayed side by side in the Evidence Drawer.
- **Hero Interaction:** The lawyer resolves the conflicting amount, edits the sentence in Tiptap, observes the check immediately turn to Stale, re-runs verification, and downloads the draft export.

## 2. Scope and Cut Line

### P0: Must Ship for Demo
- Matter management and tenant-isolated storage.
- File upload and page-aware text extraction for English records.
- Persistent conversation thread with Strands Agents SDK orchestration.
- Writer Agent, Citation Reviewer, and Fact Reviewer roles.
- Tiptap editor canvas with custom reference nodes (`citationRef`, `factRef`).
- Sliding Evidence Drawer with tri-directional linking.
- Stale-on-edit invalidation via content hash recalculation.
- Gated draft PDF and JSON package export.
- 170-second continuous demo video.

### P1: Post-P0 Enhancements (Time Permitting)
- Full server-enforced reviewed export gate.
- Cedar authorization policy integration.
- OpenSearch retrieval integration.
- Detailed audit timeline export.

### Cut First (Out of Scope for Sprint)
- Hindi translation agent.
- Argument critic / opposing counsel mode.
- Broad web-wide corpus scraping.
- Full Form 1 statutory filing automation.
- Multi-user real-time collaboration.
- Microservice database splits (pgvector, DynamoDB, Redis pub/sub).

```text
Day 4: Polish, Hardening, and Submission
  ├── Feature freeze; fix only submission-critical defects
  ├── Run full fixture verification and isolation test suite

  └── Record final 170-second demo video and submit early
```

## 4. The 170-Second Demo Script

The official rules require a recorded video up to 3 minutes (180 seconds). The recording follows a single continuous narrative:

| Timestamp | Visual Action | Narration Objective |
|---:|---|---|
| **0 to 15s** | Finished workspace; select highlighted citation in canvas | "A polished legal draft can conceal critical citation and factual errors." |
| **15 to 35s** | Display Supreme Court ruling in *Pooja Ramesh Singh* (2026 INSC 668) | Ground the solution in real judicial sanctions and Indian court rulings. |
| **35 to 55s** | Open matter, upload two client records, prompt Main Agent | Demonstrate simple input and automated page-aware intake. |
| **55 to 80s** | Working brief renders in Tiptap; show Strands task stream | Highlight AWS Strands Agents SDK orchestration and real-time streaming. |
| **80 to 115s** | Click real citation, fake citation, and modified quote in sequence | Show separate identity, quotation, and support findings in Evidence Drawer. |
| **115 to 140s** | Open conflicting financial amount; compare both uploaded records | Demonstrate side-by-side discrepancy review and lawyer resolution. |
| **140 to 155s** | Edit sentence in Tiptap; status turns Stale; re-run check | Prove version integrity: old green checks cannot survive text edits. |
| **155 to 170s** | Export draft PDF with unreviewed findings appendix; final wide shot | Conclude with transparent auditability and professional boundaries. |

## 5. Risk Mitigations

| Risk | Mitigation Strategy |
|---|---|
| Model API rate limits mid-demo | Pre-cache responses for the primary demo path; keep local fixtures ready. |
| Live legal API downtime | Curate 8 to 15 IBC Section 7 cases into local PostgreSQL store as primary baseline. |
| Video upload deadline pressure | Record first backup video on Day 3; perform final recording on Day 4 morning. |
| Multi-agent loop timeouts | Strictly limit tool iterations and execute specialists sequentially under orchestrator. |

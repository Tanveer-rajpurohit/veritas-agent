# Demo and submission plan

## 170-second recording

| Time | Screen/action | Narration purpose |
|---:|---|---|
| 0–15s | Finished workspace; click a highlighted citation | “A polished legal sentence can hide several different failures.” |
| 15–35s | Brief problem and official *Pooja Ramesh Singh* reference | Establish a real Indian problem with a primary source |
| 35–55s | Open matter; show two uploaded records and ask Main Agent for a working brief | Show user and input |
| 55–80s | Draft artifact opens in editor; agent run shows Writer → Citation → Fact | Show Strands-based AWS integration and orchestration |
| 80–115s | Click genuine citation, invented citation, and modified quote | Show separate identity/quote/support states and exact evidence |
| 115–140s | Open conflicting amount; compare two pages; choose value with reason | Hero UI and human judgment |
| 140–155s | Edit resolved sentence; status becomes stale; rerun check | Demonstrate version integrity |
| 155–170s | Export draft/review report; final wide shot | Close with traceable review and limitations |

Use one continuous story. Avoid terminal footage unless a two-second architecture insert is necessary. Increase browser zoom so evidence text is readable in the submitted player.

## Spoken positioning

“Veritas is a matter-based drafting workspace for Indian lawyers. It links important sentences to the records and authorities behind them, separates the checks a citation actually needs, and makes edits invalidate old review. It helps a lawyer prepare and review a first draft; the lawyer remains responsible for the legal work.”

## Evidence for the problem

Cite *Pooja Ramesh Singh v. Jammu and Kashmir Bank Ltd.*, 2026 INSC 668 through the [Supreme Court's official summary](https://www.sci.gov.in/landmark-judgment-summaries/) or [official judgment PDF](https://api.sci.gov.in/supremecourt/2025/52338/52338_2025_5_1501_71939_Judgement_02-Jul-2026.pdf). Say the orders involved nonexistent citations and nonexistent attributed paragraphs; do not reduce the facts to “six fake cases.”

## What the README/write-up must include

Problem, target user, honest scope, screenshots/GIF, setup, architecture, how AWS/Strands is genuinely used, source and model choices, fixture/evaluation results, security limitations, AI coding tools used, licences/attributions, and what the team learned. Publish an AWS Builder Center post for the separate top-blog opportunity if time permits; it is not a substitute for the required submission write-up.

## Submission checklist

- University/student eligibility and team registrations complete.
- Public repository created after kickoff with event-period history.
- Licences and credit for all non-original work.
- No secrets, private client data, paid-source redistribution, or cached proprietary content.
- Clean setup verified.
- Video ≤3 minutes, captions/readable UI, public link tested.
- Short write-up explains problem, build, and AWS role.
- One submission per team, submitted before deadline; submit early because edits stop at deadline.

The event criteria are idea/impact, AWS use, learning, execution, and the demo video; Best UI focuses on design/usability. A small working feature is explicitly preferred over several incomplete ones.
